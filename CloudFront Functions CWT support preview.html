Working with the CWT module

As part of our current support, we will support the COSE MAC0 structure only. This provides support for the HMAC-SHA256 algorithm for generation of the message digest / signature. 

Token structure

CloudFront expects you to make sure the token is correctly tagged. The COSE structure tag is REQUIRED while the CWT tag is optional.
{ // CWT Tag
   { // COSE Structure Tag
        [
            protectedHeaders,
            unprotectedHeaders,
            payload  
        ]
   }
}

CWTJSON

 Both functions in the module include using the CWTJSON object. This is a JS object, defined as:
CWTJSON {
    protectedHeaders,
    unprotectedHeaders,
    payload
}

Sending the token over HTTP

You can use already available methods to send these tokens over HTTP. Example includes using the base64url encoding. The tokens can be included as part of the URI, cookies or headers. We leave this choice up to the you.

Validating a token





You will be expected to extract the base64url encoded token and decode this to a Buffer. This buffer can then be passed to the modules provided by CloudFront Functions to receive a decoded token (CWTJSON) back. CloudFront Functions will support verifying the COSE object integrity but will leave verifying the contextual claims to the you. 

The general steps to handle the token are as follows:
  • [your function code] Decode sent token to a Buffer object.
  • [cf.cwt.validateToken()] Call the CWT module to get back the decoded token as a JSON object.
    • This step will involve:
      • Identifying the sent token.
      • Decoding the sent token.
      • Verifying token integrity:
        • Verify token digest (computed MAC for Mac0). 
      • Returning the decoded token (CWTJSON), if verified.
  • [your function code] Verify the claims and take further actions.

Generating a token



This sub-section will cover the use-cases of generating a new token or “refreshing” an old token, which will be also considered as token generation. CloudFront Functions will expect you to define the tokens as JavaScript Objects, following the standards set by the RFC 8152 for the supported COSE structure. The return value will be an encoded Buffer object. The steps are as follows:
  • Define the structure as a JavaScript Object
  • Call the native generate function to encode to a COSE and return the buffer.
Notes:
  • You can use the :bstr suffix after the claim name to encode the claim value as a CBOR byte-string. The suffix is stripped away and not included when the actual encoding happens. It serves as a guidance to the encoder. An example of this is available as part of code example 2.

Claim keys

CWTs involve handling a set of claims. At the foundation level, every claim is a label : value pair. In CWTs, the label can be either an integer or a string. However, JavaScript does not support integer labels (or keys) and therefore will by default convert them to string. During the encoding phase, the module encoder will identify numbers that are represented as strings and encoding them as an unsigned or signed number. On the decode, claim keys are all represented as strings. 

You can then use enums to work with a particular claim as shown in code example 1.

Restrictions

The following restrictions apply to our CWT support on CloudFront Functions:
  • Supported COSE structures:
    • MAC0
  • Supported algorithms:
    • HMAC-SHA256 
  • Token size:
    • Currently, token size is capped at 1KB.
  • Indefinite length structures are not supported.

Code Examples

Decode token and verify claims

import cf from 'cloudfront'

const SomeKindOfClaim = {
   ZeroClaim: 0,
   OneClaim: 1,
   TwoClaim: 2
}

async function f(event) {
    let request = event.request;
    
    // Assume we transport kid as a base64url utf-8 vec, so we retrieve it in correct form
    let kid = Buffer.from(request.headers['x-cwt-kid'].value, 'base64url').toString('utf8');
    
    // Retrieve the kid from kvs
    let secretKey = cf.kvs.get(kid);  
    
    let b64_token = request.headers['x-cwt-token'].value;
    let tokenBuffer = Buffer.from(b64_token, 'base64url');
    
    let handlerContext = {
       key: secretKey,   
    }
    
    try {
        let cwt_json = cf.cwt.validateToken(tokenBuffer, handlerContext);
    
        // You can use defined enums to access the token claims.
        if (cwt_json[SomeKindOfClaim.ZeroClaim]) {
            // take some actions here...
        }
    } catch (error) {
        return {
           statusCode: 401,
           statusDescription: 'Invalid token'
        };
    }

    return request;
}

Code example 2: Generate token with a claim using the :bstr suffix

import cf from 'cloudfront';

async function f() {
    var response = {
        statusCode: 200,
        statusDescription: 'OK',
        headers: { }
    };
    
    let someTokenJSON = {
        protected: {
            1: "5",
            2: "4"
        },
        unprotected: { // The :bstr suffix here will instruct the encoder to encode -
        // - as a CBOR byte-string.
            "6:bstr": "somethingSomething",
            "someClaim": "Arsenal"
        },
        payload: {
            5: "cloudfront",
            6: 1.3104913,
            30: {
                2: {
                    1: 3194181313
                }
            }
        }
    };

    let genContext = {
        cwtTag: true, // Means that the cwtTag should be added.
        coseTag: "MAC0",
        key: "testKey"
    }

    let tokenBuffer = cf.cwt.generateToken(someTokenJSON, genContext);
    response.headers['x-cwt-token'] = { value: tokenBuffer.toString('base64url') };
    
    return response;
}
